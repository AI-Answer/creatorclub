# Point Permutations

Combine one point architecture, one illustration mode, one framework mode, and one transition mode. Vary combinations across points.

## Point architectures

| Architecture | Structure |
|---|---|
| Principle | claim → why → illustration → model → application |
| Problem / cause / fix | symptom → hidden cause → correction → example → action |
| Myth / truth | belief → contradiction → proof → replacement model → action |
| Step | action → reason → demonstration → checklist → next step |
| Before / shift / after | old approach → turning point → result → rule → application |
| Decision | situation → options → tradeoff → decision rule → choice |
| Failure analysis | attempt → failure → diagnosis → framework → prevention |
| Case study | context → move → result → extracted model → replication |
| Comparison | option A → option B → contrast → selection model → decision |
| Demonstration | prediction → demonstration → observation → principle → practice |

## Analogy and example modes

- Everyday analogy: kitchen, map, fitness, traffic, building, game, or conversation.
- Concrete scenario: place the target viewer in a realistic moment.
- Demonstration: show the mechanism operating step by step.
- Case study: use a real, user-supplied case with context and outcome.
- Counterexample: show where the common rule fails.
- Before-and-after: contrast behavior or result.
- Numerical example: use supplied or clearly hypothetical numbers.
- Personal story: use only user-provided experience.

Label hypothetical examples as hypothetical. Avoid analogies that distort the mechanism.

## Framework modes

- Named steps: three to five short verbs.
- Acronym: use only when natural and memorable.
- Equation: input + mechanism = outcome.
- Checklist: observable yes/no conditions.
- Decision rule: “If X, do Y; otherwise, do Z.”
- Spectrum: low ↔ high with meaningful positions.
- Matrix: two axes and four choices.
- Ladder: progressive levels of mastery.
- Loop: repeatable cycle with feedback.
- Filter: criteria that remove weak options.

Name a framework after its real mechanism, not for cleverness alone.

## Transition modes

- Sequence: the next point is the prerequisite or consequence.
- Contrast: the next point corrects a limitation.
- Escalation: the next point has greater leverage.
- Question: open a specific unresolved question.
- Callback: connect back to the hook or prior example.
- Cause and effect: show that the current point creates the next problem.
- Zoom: move from principle to tactic or tactic to system.

## Full script map

```text
Hook
→ Main setup
→ Transition
→ Point 1: setup → structure → analogy/example → framework → application/payoff
→ Transition
→ Point 2: setup → structure → analogy/example → framework → application/payoff
→ Transition
→ Point 3: setup → structure → analogy/example → framework → application/payoff
→ End-screen setup
→ CTA
```

Use fewer or more points when the promise requires it. Three is a common pattern, not a mandatory count.
